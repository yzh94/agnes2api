# 专有概念

## ClientKey

**位置**: `models/database.py::ClientKey`

客户端 API Key，用于身份认证和配额管理。

**关键字段**:
- `id`: 主键
- `user_id`: 关联用户
- `key`: API Key 字符串
- `status`: active/disabled
- `quota`: 配额限制（-1 表示无限）
- `used_quota`: 已用配额

**不变量**:
- key 必须唯一
- 每个用户只能有一个 ClientKey

## UpstreamKey

**位置**: `models/database.py::UpstreamKey`

上游 Agnes API Key，用于转发请求到 Agnes 模型。

**关键字段**:
- `id`: 主键
- `user_id`: 归属用户（可为 null，表示全局 key）
- `key`: API Key 字符串
- `weight`: 负载均衡权重
- `status`: active/disabled
- `disabled_reason`: 禁用原因

**不变量**:
- key 必须唯一
- status 为 disabled 的 key 不参与负载均衡

## UsageLog

**位置**: `models/database.py::UsageLog`

请求用量记录，存储每次调用的 token 消耗。

**关键字段**:
- `id`: 主键
- `user_id`: 用户 ID
- `client_key_id`: 客户端 Key ID
- `upstream_key`: 使用的上游 Key（脱敏前缀）
- `model`: 模型名称
- `tokens`: token 数量
- `cost`: 费用

**写入时机**: 每次成功请求后异步写入

## KeyPool

**位置**: `service/redis_key_pool.py::KeyPoolManager`

上游 Key 池，实现负载均衡与自动降级。

**关键功能**:
- `get_next_key()`: 获取下一个可用 Key
- `record_success(key)`: 标记 Key 成功
- `record_failure(key)`: 标记 Key 失败
- `start_health_checker()`: 启动健康检查定时任务

**算法**: 加权轮询（Weighted Round-Robin）

## LLMContentLog

**位置**: `service/llm_content_logger.py::LlmContentLogger`

LLM 请求内容日志，JSONL 格式持久化到文件。

**字段**:
- timestamp, request_id, user_id, client_key_id
- endpoint, stream, model
- input (完整请求 payload)
- output (完整响应)
- duration_ms, first_chunk_ms
- upstream_key_prefix (脱敏)

**写入规则**:
- 仅记录成功请求
- 异步写入，不阻塞主流程
- 按天分文件
